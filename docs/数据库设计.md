# 《喵游记》数据库设计（第一版）

> 依据：`docs/游戏规则设计.md` v1.5 + 2026-09-16 设计访谈结论。
> 范围：核心单机循环（账号/角色/道具/装备/技能/任务/怪物/地图/商店/货币）。
> DDL：`db/schema.sql`（含每表示例数据）。社交与日志系统本期不建表，见文末预留清单。

---

## 1. 全局约定

| 项 | 约定 |
|---|---|
| 版本 | MySQL **8.0.16+**（需要 CHECK 约束与表达式默认值） |
| 引擎/字符集 | InnoDB / utf8mb4 / utf8mb4_0900_ai_ci |
| 架构 | **单服单库**，所有表不带 `server_id`；将来分区服再迁移 |
| 主键 | `BIGINT UNSIGNED AUTO_INCREMENT` |
| 命名 | 配置表 `cfg_` 前缀；玩家表 `character_` 前缀（账号 `accounts`、角色 `characters` 除外） |
| 外键 | **保留物理外键**（单服页游规模下数据完整性优先） |
| 时间 | 全表 `created_at` / `updated_at DATETIME(0)`，`DEFAULT CURRENT_TIMESTAMP / ON UPDATE CURRENT_TIMESTAMP`；**所有连接会话时区必须设为 UTC**（如连接串 `time_zone=+00:00`），入库即 UTC，展示层自行换算 |
| 软删除 | 仅 `characters` 使用 `deleted_at`；删除时应用层将 `name` 改为 `#<id>#<原名>` 释放昵称（回收期后可彻底清理） |
| 货币 | 金/银/铜统一存**最小单位** `BIGINT UNSIGNED`（铜币），金银只是展示换算；不用浮点 |
| JSON | 只用于「自由结构参数」（技能效果/任务目标/掉落参数/词条），可查询的关联一律建列 |
| 注释 | **每个字段必须带 `COMMENT`**（中文），索引/约束不强制 |

## 2. 关键设计决策（访谈结论）

1. **一账号最多 5 角色**：`accounts` 与 `characters` 分表；上限由应用层校验（MySQL 无跨行计数约束，不为此加触发器）。
2. **角色名全服唯一**：`uk_characters_name (name)`；软删改名方案见上表。
3. **配置进 MySQL**：怪物/道具/装备/技能/任务/地图/商店均为 `cfg_` 表，便于调平衡与程序化导入清单数据；后端加载时自行加缓存。
4. **道具三段建模**：`cfg_item_templates`（全道具含装备；含丢弃/出售/掉落/使用/快捷标记、品质展示色、单位量词）→ `cfg_equipment_templates`（装备扩展，1:1）→ `character_inventory`（玩家实例，含强化等级/连续失败次数/孔位/词条）。
5. **背包格子制**：`(character_id, slot_index)` 唯一；容量 300 由应用层校验；**已穿戴装备 `slot_index` 为 NULL**（MySQL 唯一索引允许多行 NULL），穿戴状态记录在 `character_equipment`。
6. **装备位独立表 + 部位配置表**：`character_equipment` 每个部位一行，`inventory_id` 全局唯一（一件装备只能穿一处）；穿/脱 = 移动 `slot_index` 与增删装备位行。**部位本身是配置表 `cfg_equipment_slots`**（code/名称/排序），新增部位（饰品、守护之星等）只需插一行配置，零 DDL、零迁移；`cfg_equipment_templates.slot_id` 与 `character_equipment.slot_id` 均外键引用它。
7. **任务四表**：模板 / 目标（type+JSON params）/ 角色任务状态 / 目标进度。周期任务用 `cycle_key`（日常=日期、周常=ISO 周、非周期=空串）实现可重复接取。
8. **怪物掉落独立表**：支持「按道具反查来源怪物」；技能列表用 JSON（无反查需求）。
9. **商店限购**：`cfg_shop_items.daily_limit` + `character_shop_buys` 按 `(角色, 货架, 日期)` 计数。
10. **等级经验配置表**：公式 `floor(100×lv^1.5)` 落成 `cfg_levels`，策划调表不触发代码变更。
11. **怪物斩杀统计**：`character_monster_stats` 按（角色 × 怪物）一行聚合 `kill_count` 与 `total_exp_gained`；战斗胜利时 `INSERT ... ON DUPLICATE KEY UPDATE` 递增（注意经验受等级惩罚/加成修正，应累加**实际获得值**而非模板值），结算界面按行读取展示。

## 4. 口径差异说明

| 差异点 | 规则文档 | 本设计采取 | 理由 |
|---|---|---|---|
| 装备部位 | 8.2 节为 6 部位 | **12 基础部位 + 可扩展**（与装备清单、原型装备栏一致） | 12 部位是超集，兼容两者；部位存于 `cfg_equipment_slots` 配置表，收缩/扩展只需增删配置行 |
| 货币 | 9.1 节为金币/钻石/鱼干币 | **金银铜三种**（当前决策） | 访谈最新结论；`currency_type` 用 VARCHAR，将来加钻石/鱼干币零迁移 |
| 道具品质 vs 装备品质 | — | 道具品质**黑/绿/蓝/紫/橙**挂 `cfg_item_templates.quality`（展示色）；装备品质**灰/绿/蓝/紫/橙**沿用装备清单口径挂 `cfg_equipment_templates.quality` | 两套口径独立（最低档命名不同：黑 vs 灰）；若要统一，删装备表 quality 列并做一次「灰→黑」映射即可 |

## 5. 应用层负责的校验（不进数据库）

- 一账号 ≤ 5 角色；背包 ≤ 300 格；技能等级 ≤ 角色等级。
- 装备穿戴的 `slot_id` 必须与 `cfg_equipment_templates.slot_id` 一致（跨表一致性，由服务在穿脱事务中校验）。
- 周期任务的 `cycle_key` 生成（日常/周常）与非周期任务的空串。
- 金/银/铜展示换算（如 1 金 = 10000 铜，汇率由策划定义）。
- 怪物属性可按 11 章公式批量生成后写入 `cfg_monsters` 再微调。
